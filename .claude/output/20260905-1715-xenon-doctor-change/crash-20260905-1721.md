# The 17:21 freeze, read from the logs

<!-- sessions: pad-steam-7c@2026-09-05 -->

The Mac froze at about 17:21 on 2026-09-05 and the owner held the power button. This note says what the logs show, in time order, and what it means for the fix. Log extracts live next to this note in `evidence/` (`crash-kernel.txt`, `crash-bluetoothd.txt`, `crash-errors-windowserver.txt`, `boot-shutdown.txt`, `reconnect-fail.txt`, and the `steam-console-*.txt` captures); the Steam lines are quoted from `~/Library/Application Support/Steam/logs/`.

## Not a kernel panic

No `.panic` file exists in `/Library/Logs/DiagnosticReports`. The kernel kept writing normal Wi-Fi lines until 17:22:12. The next boot logged `*UNEXPECTED SHUTDOWN DETECTED*` at 17:23:05. So the kernel stayed alive and the display stack stopped responding. That is a user-space hang.

## A correction, measured at 17:55

The `exit code 137` on the wrapper is routine. A clean quit from the game's own menu at 17:55:03 produced the same two lines, `exit code -1` for the game and `exit code 137` for the wrapper, in `gameprocess_log.txt`. Steam always kills the wrapper script when the game child exits. So those two lines at 17:20:34 do not prove the Stop clicks did anything unusual. The force-kill half of the story below is weaker than first written; the virtual-device churn half stands, and it was still present, at a lower rate, during the clean run at 17:50 to 17:55.

## What it means

Two things were true at once when the freeze began. Steam was thrashing virtual input devices in response to the Home button and focus changes. The game had been force killed while its window and surfaces were still registered with the window server. The logs cannot say which of the two was sufficient on its own. The owner reports the same freeze once before, on the M5 Air, also with Stardew Valley, so this is a repeatable pattern and not a one-off.

## What changes in the plan

1. Steam Input for PlayStation controllers goes off. The game already reads the pad directly (the empty override in row 1 of the matrix), so nothing is lost. With it off, Steam never builds virtual keyboard and mouse devices for the pad and the Home button never opens the Steam overlay. This removes the first half of the freeze.
2. The app's "quit a stuck game" repair sends a normal quit first and waits. It never sends a kill signal while the game window is on screen. This removes the second half.
3. The guide tells the owner: to turn the pad off during a game, use the pad's own power hold only after the game is closed, or use the app's button, because a long Home press is also ten Guide presses to Steam.
4. The app watches for a game that Steam still lists as running after its window is gone, and offers the graceful quit, because that is the state the owner was in when he reached for Stop.
